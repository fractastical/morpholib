# Problem-Fixer fix-007 — Planarian stale specimen pins (LIB-MEAS-02)

## Finding

On `main`, `morphoeval/audits/2026-10-19-planarian-hk-atpase-anterior-audit-v2.measurements.yaml` still pinned `schmidtea_mediterranea_specimen.jpg` to digest `466029cc0561067890bb0f69d224d8f799745eeb67a0699246107611737fb546` and claim-boundary text `length=1478 px` / `x/L=0.0528`. The committed specimen file hashes to **`0dde9f5e83a87dd9bdc3627e19ebc891cb4f8e99cf632fe637bccf082abfb990`** at **720×500 px** (segmentation body length **626 px**), matching `models/2011-beane-planarian-hk-atpase-anterior.py` since Pass 3 Phase B (commit `398c37e0`).

## Root cause

The specimen swap was applied in the simulation script and noted in the math KG (`pk:evidenceAgainst`), but the v2 audit sidecar, `planarian_hk_atpase_anterior_reference.json`, dataset README, and `scout_manifest.json` were not updated together. A secondary issue blocked regeneration: the v2 audit YAML pointed at `2011-beane-planarian-hk-atpase-anterior.py` at repo root while the script lives under `models/`, so `measure_outputs.py` could not call `measure_morphoeval()`.

## Fix

1. Updated dataset provenance (`reference.json`, `README.md`) to the live SHA-256, dimensions, and PlanformDB commit note.
2. Added a `committed_specimen` block to `scout_manifest.json` (Wikimedia candidates retained as historical scout output).
3. Corrected `claim_boundary.reconstructed_in_script` in the v2 audit YAML and set `script:` to `models/2011-beane-planarian-hk-atpase-anterior.py`.
4. Regenerated the sidecar with:

   ```bash
   python3 morphoeval/measure_outputs.py morphoeval/audits/2026-10-19-planarian-hk-atpase-anterior-audit-v2.yaml
   ```

   (Locally rendered `docs/media/planarian_hk_atpase_anterior_comparison.png` was present for fingerprinting; it is not tracked in git. The tracked GIF digest `4b0de2e5…` matches the sidecar.)
