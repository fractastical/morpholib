# Problem-Fixer fix-003 — Rule 30 Delphi artifact sync

## Finding

Scout **scout-010-c** flagged a risk that `docs/open-problems.json`, embedded `DATA.DELPHI` in `docs/problem-graph.html`, and `morphoeval/audits/2026-10-20-rule30-grand-prizes-bayesian-delphi.yaml` could drift on OP-01..OP-03 bridge pooled posteriors and mis-color MorphoSwarm viability relative to the ≥15% “possible pathway” classification threshold.

On the current tree, **no drift** was present. All three sources match within the agreed tolerances.

## Root cause

None for this snapshot — artifacts were already aligned. The gap was **missing automation**: `docs/build_problem_graph_html.py` `validate()` checks internal graph coherence but did not compare against `open-problems.json` or the audit YAML.

## Fix

Added **`morphoeval/problem_scouts/verify_rule30_delphi_sync.py`**, which:

1. Reads OP-01..OP-03 pooled percentages from `docs/open-problems.json`.
2. Parses `DATA.DELPHI[p1|p2|p3].pooled.posterior` from `docs/problem-graph.html`.
3. Loads YAML truth from `audit.panel_consensus.problems[…].bridge_pooled.posterior_logodds_pooled` (×100 for percent).

Checks:

- `|open-problems − graph| ≤ 0.6` percentage points per prize.
- YAML vs open-problems and YAML vs graph: ≤ **0.01% relative** error, with a **0.01 pp** floor for display rounding (2–3 decimals in the graph feed).

On failure, prints offending **OP-01 / OP-02 / OP-03** lines to stderr and exits 1.

Added **`tests/test_problem_fixer_delphi_sync.py`**: repo smoke test, synthetic OP-01 drift detection, tolerance unit check.

No hand-edited Delphi scores; no changes to `docs/open-problems.json` or `docs/problem-graph.html`.
