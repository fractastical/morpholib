# Problem-Fixer fix-010 — Planform damaged-negative CI gate

## Finding

Scout candidate **scout-079-c** reported that `datasets/planform/damaged/manifest.json` defines five single-fault Planform bioelectric negatives with pinned `expected_error_code` values and sha256 digests, and that `python3 models/planform_bioelectric.py --self-test` validates them when run manually. Reproduction on the current tree confirmed: `--self-test` passes all five damaged checks (regeneration skipped without `PLANFORM_DB_PATH`). No pytest module previously referenced the damaged manifest, so the standard `python3 -m pytest tests/ -q` path did not gate this contract.

## Root cause

Validation logic was embedded in the CLI self-test only. MorphoEval / AGENTS.md cloud validation cites `compileall` and pytest, but no test file imported or asserted the damaged-negative manifest, leaving a gap between the fail-closed design and automated CI discovery.

## Fix

1. **`models/planform_bioelectric.py`** — Extracted `check_damaged_negative_item()` and `check_all_damaged_negatives()` as the shared source of truth for manifest-driven checks (error codes via `validate_fixture` / `error_codes`, sha256 pins). `self_test()` now delegates per-file checks to these helpers while preserving existing pass/fail console messages.

2. **`tests/test_planform_damaged_negatives.py`** — New pytest module that:
   - Asserts the manifest lists exactly five negatives with the expected `E_*` code set.
   - Parametrizes over all committed damaged files (no fixture mutation).
   - Calls `check_all_damaged_negatives()` for a single aggregate gate.
   - Includes negative-control tests on **temporary copies** under `tmp_path`: a flipped `expected_error_code` must fail, and a schema corruption must fail even when the manifest code is unchanged.

No GitHub workflow files were modified; discoverability via pytest is the deliverable.
