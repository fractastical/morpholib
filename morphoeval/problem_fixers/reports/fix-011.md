# Problem-Fixer fix-011: Lean formula alignment gate

## Finding

`morphoeval/verify_integrity.py` Rule 3 rejects vacuous Lean theorems (unused quantifiers, ground arithmetic) but does **not** ask whether the YAML `formula` string describes the same objects as the paired `lean_code` `def`. The overnight expansion templates in `run_overnight_1000_loops.py` emit generic stubs:

- `def law1_invariant (a b : Int) : Int := a * b`
- `def law2_balance (p q : Int) : Int := p + q - q`
- `def law3_threshold_margin (lhs rhs : Int) : Int := lhs - rhs`

Those theorems can still be classified as **structural** while the `formula` field names physical quantities (`alpha_f`, `D_ij`, `J_ij`, …). The pilot stub loop `zhou-ginkgo-yimaensis-flux-canalization.yaml` (tagged `lean_verification: placeholder_not_mechanism_proof`) is a concrete example.

## Root cause

Integrity tooling stopped at signature/quantifier shape after the 2026-10-24 incident (`model_integrity_ledger.jsonl`); no mechanical bridge enforced **formula ↔ Lean def** semantics. Mass-generated loops inherited the same three stub defs with per-loop formulas filled in from catalog metadata.

## Fix

New checker: `morphoeval/check_lean_formula_alignment.py`.

Per equation:

1. Parse the first Lean `def` (parameters + body).
2. **Stub path:** if the def matches the overnight templates above, require every physics token from `formula` (identifiers with `_` or length ≥ 5, after Unicode→ASCII normalization) to appear in the def, and forbid generic stub parameter names when the formula is physics-rich.
3. **Mechanism-linked path:** otherwise require each def parameter to be reflected in `formula` and/or `variables` (including abbreviations such as `kf` ↔ `kx0_final` via ordered subsequence matching on documented symbols).

CLI:

```bash
python3 morphoeval/check_lean_formula_alignment.py morphoeval/math_kg_loops/<sim>.yaml
python3 morphoeval/check_lean_formula_alignment.py --self-test
```

Focused tests: `tests/test_lean_formula_alignment.py`.

## Residual risk & safe rollout

- **Do not** mass-rewrite ~3k placeholder YAML/Lean files in this fixer wave. Expect most expansion-template loops to **fail** this gate until Lift/mechanism work replaces stubs.
- Rollout suggestion: run the checker in **report-only** CI first (or filter to loops without `lean_verification: placeholder_not_mechanism_proof`), then block merges on failures for newly touched loops, then pilot on cohort IV (phyllotaxis/auxin) where zhou already documents the stub issue.
- Mechanism-linked loops (e.g. forterre) rely on parameter↔symbol reflection heuristics; edge cases with very abstract Lean encodings may need human review even when the checker passes.
